CONFIGURATION REVIEW - CONFIG INSPECTOR 5.15.0

Guidance revision: 2026.10.24

Purpose
Review recognized imported configuration locally and provide evidence, affected records, configuration locations, recommended changes and verification steps. No device is contacted and no settings are changed.

Assessment categories
Issue: a contradiction or invalid value confirmed by the recognized configuration.
Recommendation: a security or design choice requiring administrator review.
Retained setting: an inactive or explicitly disabled entity; omitted from the default findings list. Explicitly disabled time synchronization and remote logging remain recommendations because the disabled protective function is the setting being reviewed.

Coverage
Every registered check has a positive regression test. A check is assessed only where required recognized inputs are available. Not assessed is distinct from no issue found. No percentage, compliance score or certification is inferred. The review time and guidance revision accompany exports.

Vendor handling
Common normalized addressing, VLAN, route, DHCP, policy and object-group structures are reviewed across supported vendors. Explicit FortiOS, Cisco/HPE CLI, Junos, PAN-OS XML, Sophos XML, SonicOS fields and typed RouterOS data add vendor-specific checks. Individual checks can remain unassessed if an export omits the fields, the schema is unknown, or binary fields are not interpreted. Exact duplicate policy comparison is limited to recognized FortiOS and PAN-OS explicit rule fields. Cisco password storage types are interpreted only for Cisco imports.

Exceptions and interpretation
Routing contexts and VRFs are kept separate. IPv4 /31 and /32 interfaces and IPv6 link-local reuse are not treated as ordinary host/subnet conflicts. Known DHCP exclusions can suppress allocation conflicts. LDAP port 389 alone is not treated as plaintext: TLS/StartTLS settings are inspected. Deleted and deactivated Junos service statements are not revived. AEAD proposals do not require a separate integrity algorithm. Disabled profiles are kept separate. Rule comparisons include explicit conditions and profiles, and do not claim general firewall shadowing. Explicit DNS recursion does not establish internet exposure. Logging over UDP/TCP may be protected by a tunnel or management network.

Certificates
Reads unambiguous ISO date metadata and bounded DER validity fields from PEM X.509 certificates, supporting UTCTime and GeneralizedTime. Flags expired, future-dated and 30-day renewal cases using the displayed review time. Certificate consumers are resolved in context when possible. Signature, trust-chain, revocation and hostname validity are not certified. Ambiguous calendar formats, malformed DER and unknown metadata are not assigned guessed dates.

Privacy and exports
The imported model, original entries, ownership and record IDs are not changed. Credentials are omitted from review evidence and HTML/TXT/JSON exports, including source command evidence that may contain secrets. Exports include the selected context and filters, coverage, resolution steps, verification and source references. Review data is held in memory and cleared with the workspace. The original source remains accessible through existing record links.

Boundaries
This is a configuration rules review, not a network reachability test, firmware CVE feed, CIS certification or substitute for platform-specific change validation. A configuration can intentionally use HA/anycast, recursive next hops, coordinated DHCP, inherited settings or external MFA. Those possibilities are stated where relevant. Test required access and recovery paths before applying changes.
