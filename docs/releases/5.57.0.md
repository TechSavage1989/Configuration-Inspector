# Config Inspector 5.57.0

## Real hardware on the diagram

- **Models from their ports:** when a configuration names no model, the app works it out from the ports where only one model fits: Catalyst 9500-24Y4C and 48Y4C, and the MikroTik CRS326-24S+2Q+RM (from an export or a binary backup). Where several models share the same ports, it uses their common layout: the Catalyst 3560E 48-port (with its two X2 slots, Gi0/49-52 on TwinGig converters and Te0/1-2) and the CX 6000 / 6100 12-port. These devices no longer get a blank faceplate.
- **Modular chassis:** an HPE 5406R or 5412R zl2 (and other chassis whose configuration lists its modules) is drawn as its modules in slot order. Each card carries its slot letter and model and has the module's real ports, such as an 8-port SFP+ or a 24-port PoE+ module.
- **Mixed stacks:** stack members of different models (such as JL558A and JL256A in one VSF stack) are each drawn and named as their own model, on the diagram and on the port map.

## Uplinks on the right ports

- **Aggregated uplinks:** a link aggregation is drawn as one link per member port. When the far end's uplink ports name no device (for example "uplink_to_core"), they are used if there are as many of them as near-end members. An MDF's five ports to an IDF stack now land on the stack's five uplink ports instead of one unnumbered spot. Ports are paired in port order, and the link's details say so.
- **Closest name wins:** a port described for an older switch with a similar name (such as "...-IDF-SW01") is no longer taken as an uplink to the "...-IDF-STACK".
- **Gateway links** prefer an aggregated trunk and skip disabled ports, and pair the members when both ends are aggregated.

## Port maps

- **Legend on every page:** the port role legend now heads every port map page, not only the last.
- **Models per member:** each stack member's and chassis module's heading shows its own model.
